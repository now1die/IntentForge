# Candidate generation and ranking

Phase 8.5 requires trusted typed examples. Input-only observations and declared
bounds supply context. They never fill missing expected outputs. The engine
rejects conflicting expectations that refer to the same typed input.

A successful static projection contributes evidence in the shared proposal
contract. Selection within each new component uses token edit cost and source
order. The shared deterministic ranking, compilation, AST-level deduplication
and candidate budget apply to the integrated pool. The existing worker can
reorder the same candidates using observed agreement. Observed matches support
review under the existing original-mismatch and unique-candidate rule.

The static engine does not run Mini-C source. The benchmark cross-checks
projected candidates with the interpreter, and the live evaluation uses the
isolated worker to establish discovery and holdout outcomes.
